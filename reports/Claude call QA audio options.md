# Claude cannot hear your calls, so transcribe first

**Claude does not listen to audio. As of 20 November 2026, nothing in Anthropic's published documentation shows Claude, the Anthropic API or Claude Cowork accepting a phone recording and "hearing" it.** Claude reads text, images and documents, so a recording has to be turned into a written transcript by a separate speech-to-text (STT) service before Claude can score it. If your Cowork setup appears to "listen", something else is almost certainly producing a transcript first: a phone-system feature (Quo transcripts are one candidate), a connector, or a script Claude runs. Check which, because the quality of the scoring can only be as good as that transcript. This matters most for Innovate: no vendor publishes accuracy figures for South African English mixed with Zulu or Afrikaans on telephone audio, and speech engines make most of their mistakes on numbers, names and IDs, which are exactly what a sales QA scorecard checks (prices, policy numbers, consent). The sound-based parts of a call, such as tone, silence and talking over each other, are invisible to Claude unless the STT tool writes them out as text. The sensible design is: pick the best transcription engine by testing 20 to 30 of your own calls, send stereo recordings where possible, have Claude score against your written scorecard with word-for-word quotes, check those quotes by program, and keep a human in charge of any score that affects an agent. Several important points below could not be verified, and this report labels them.

## Claude takes text, images and documents, not sound

**Verified from official documentation.** The Messages API reference lists the content types Claude accepts as text, image, document (PDF or plain text) and tool-related blocks, with no audio type ([Messages API reference](https://platform.claude.com/docs/en/api/messages)). Anthropic's feature overview likewise lists PDF and image ("vision") support as the media features and mentions no audio or speech feature ([Features overview](https://platform.claude.com/docs/en/build-with-claude/overview)). The clearest direct statement comes from Anthropic's OpenAI-compatibility page: audio and file inputs are not supported, and a request containing an `input_audio` part returns an error (HTTP 400) ([OpenAI SDK compatibility](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk)). One caveat on method: the researcher read only an excerpt of the very large API reference page, so the absence of audio there is strong but not exhaustive evidence. One secondary website claims the API processes audio; it contradicts the official documentation and should be treated as wrong.

**The Claude apps' voice features do not help.** Voice mode and dictation convert your live speech into text, then delete the recording ([Use voice mode](https://support.claude.com/en/articles/11101966-use-voice-mode)). File upload accepts documents and images only; audio is not listed ([Upload files to Claude](https://support.claude.com/en/articles/8241126-upload-files-to-claude.md)). July 2026 coverage says voice mode now runs on Opus and Sonnet, but describes it as a turn-based design (speech to text, then the model, then spoken reply), not a model that hears audio ([9to5Mac](https://9to5mac.com/2026/07/23/anthropic-upgrades-claude-voice-mode-with-more-powerful-models/)). Playing a call out loud into a microphone is technically possible but gives poor quality and no speaker separation, so do not do it.

**Cowork specifically.** Cowork's own list of understood file types covers Word, PDF, text, Markdown, HTML, JSON, CSV, Excel, PowerPoint, images and code, with no audio ([Claude Cowork](https://claude.com/product/cowork)). Cowork has dictation (your voice to text) but not voice mode. No official source says Cowork transcribes a dropped-in audio file. The research team had no Cowork access and did not test this, so what happens when you drop an mp3 into Cowork is **unverified**. The most likely explanations for your belief that it "listens" are that Claude wrote and ran a transcription script in its workspace (possible, see next section), that a connector delivered a ready-made transcript, or that the call had already been transcribed upstream. Claude Code and cloud platforms follow the same pattern: Claude Code's /voice is live dictation, unavailable on API-key, Bedrock, Vertex or Foundry setups ([Voice dictation](https://code.claude.com/docs/en/voice-dictation)), and the standard AWS design pairs Amazon Transcribe with Claude on Bedrock ([AWS ML blog](https://aws.amazon.com/blogs/machine-learning/unearth-insights-from-audio-transcripts-generated-by-amazon-transcribe-using-amazon-bedrock)). No roadmap announcement for native audio input was found, so plan around a transcription step, and recheck Anthropic's release notes before locking in a design.

## Cowork skills can score and make PDFs, but running transcription inside Cowork is fragile

**What a skill is.** A skill is a folder containing a required SKILL.md file (a name, a description of when to use it, and instructions) plus optional reference files and scripts, uploaded as a ZIP under Customize > Skills ([Use skills in Claude](https://support.claude.com/en/articles/12512180-use-skills-in-claude)). Claude decides when to use a skill from its description alone, so the description should list triggers such as "call recording", "transcript", "QA scorecard" and "PDF report"; if it does not fire, you can name the skill in your prompt. Skills require "Code execution and file creation" to be switched on. On Team and Enterprise plans an owner can provision a skill to everyone or share it with people or groups; shared skills are view-only and stay off until each recipient enables them ([Provisioning and managing skills](https://support.claude.com/en/articles/13119606-provisioning-and-managing-skills-for-your-organization)). Anthropic's authoring advice is to keep SKILL.md under 500 lines, put bulky material (like your scorecard) in separate reference files, and use pre-written scripts for anything that must be exact, such as arithmetic and PDF layout ([Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices.md)). A natural layout for Innovate is a skill with the scorecard in a reference file and a script that builds the PDF. That is a design suggestion, not something anyone has tested.

**Where Cowork's code runs, and what it can reach.** Cowork uses the same architecture as Claude Code inside Claude Desktop, and Claude can only read and write folders you have connected ([Cowork overview](https://claude.com/docs/cowork/overview.md); [Get started](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork.md)). Shell commands run in a Linux virtual machine whose internet access depends on a setting under Settings > Capabilities. With network access off, only Anthropic hosts are reachable. With "Package managers only", common package registries and github.com are added, download-only. "All domains" opens everything unless your organisation applied a stricter configuration ([Network access](https://claude.com/docs/cowork/guide/network-access.md)). Connectors are handled outside this virtual machine, so the restriction does not apply to them. Anthropic's docs describe Cowork running both on your computer and on Anthropic's servers in different places, so check which applies to you. The documentation does not list preinstalled software, memory or time limits. The only numbers come from a user's self-reported gist: Ubuntu 22.04, Python 3.10, about 3.8 GB of memory, 2 to 4 processor cores, and no mention of ffmpeg, the audio conversion tool ([simonw gist](https://gist.github.com/simonw/35732f187edbe4fbd0bf976d013f22c8)). These are indicative only.

**Why Whisper inside Cowork is a gamble.** Running a local transcription model needs three things: audio-conversion software, a Python package from PyPI, and a model file, usually downloaded from huggingface.co. Whisper-style skills commonly download roughly 150 MB for the base model on first run ([ClawHub audit page](https://clawhub.ai/josunlp/whisper-transcribe/security-audit)). The documented allowlist options guarantee package registries and github.com, but Hugging Face is not named, and whether PyPI is included is not stated explicitly. Nobody has published a tested example of Whisper running in Cowork, and speed on a 4 GB virtual machine is unmeasured. Whisper is also the weakest option for Zulu: a vendor-run comparison reports Whisper Large v3 at 93.4% word error rate on Zulu, against 34.6% for ElevenLabs Scribe ([ElevenLabs Zulu STT](https://elevenlabs.io/speech-to-text/zulu)). Even in the best case, then, "Claude runs Whisper in Cowork" would likely transcribe the Zulu parts badly. Your administrator could add the Hugging Face hosts under "Additional allowed domains", but that fixes only the download, not the accuracy.

**Better routes to a transcript.** The sturdiest approach is a connector that delivers transcripts. Quo's connector, visible in this environment, exposes call-transcript and call-list tools; whether every call gets a transcript depends on your Quo plan, which the documentation states inconsistently (Business and Scale, or Business only) ([Quo support](https://support.quo.com/core-concepts/calling/summaries-and-transcripts)). Third-party vendors market Cowork connectors for AssemblyAI and Gladia that accept audio files, seen only through search summaries ([Composio AssemblyAI for Cowork](https://composio.dev/toolkits/assemblyai/framework/claude-cowork.md)). Meeting-recorder connectors (Zoom, Fireflies, Otter, Granola) exist per vendor blogs but are built for meetings, not for your phone system. The other simple route is transcribing outside Cowork and dropping a text, Word or CSV transcript into the connected folder. For output, Cowork produces formatted documents, and Anthropic ships a `pdf` skill; a PDF script can use the reportlab library, though its availability in Cowork's environment is unconfirmed. Whatever the route, tell the skill to treat transcript text as data, not instructions, since a transcript is untrusted input.

## No engine is proven for South African phone calls, so test on your own recordings

**What each vendor claims on languages.** The honest summary is that coverage varies and accuracy on your kind of audio is unpublished. The table gives only what the sources support.

| ElevenLabs Scribe v2 | Zulu page exists ([ElevenLabs](https://elevenlabs.io/speech-to-text/zulu)) | $0.20 ([pricing](https://elevenlabs.io/pricing/api)) | accuracy figures are vendor-run; keyterms +$0.05/h |

| Google Chirp 3 | Zulu in Preview; Afrikaans and en-ZA not confirmed ([docs](https://docs.cloud.google.com/speech-to-text/docs/models/chirp-3)) | reseller about $0.96 | no official rate found |
| AssemblyAI | Zulu and Afrikaans not named in any result ([models](https://assemblyai.com/docs/getting-started/models)) | $0.15 to $0.21 ([pricing](https://www.assemblyai.com/pricing.md)) | strong contact-centre tooling, language fit unconfirmed |
| OpenAI gpt-4o-transcribe | no Zulu figure found | about $0.36 | has a diarization variant |

The key point is that no independent test of en-ZA telephone audio exists for the commercial engines. The closest evidence is AfriSwitch, a 2026 dataset of real code-switched African speech where the best of five systems averaged **35.93% word error rate**, far above ordinary single-language figures ([AfriSwitch](https://arxiv.org/pdf/2608.26434)); whether Zulu and Afrikaans were included was not confirmed, and the figure was seen only in a search summary. Your calls are mostly English with Zulu or Afrikaans words dropped in, which favours multilingual engines over single-language ones. That is an inference, not a finding. Quo's built-in transcripts cover "40+ languages" with no published accuracy and no confirmation of Zulu or Afrikaans, so treat them as good for search and rough summaries, not QA-grade evidence.

**Telling the speakers apart.** The most reliable method is recording the agent and customer on separate stereo channels, transcribing each channel separately and merging by timestamp, which removes guesswork about who spoke ([Medallia/Voci](https://docs.medallia.com/voci/audio-capture/audio-data-and-accuracy/single-channel-mono-and-channel-separated-audio)). If you only have mono recordings, engines infer speakers; the best of the tested diarization models in a 2025 benchmark still got about **11% of the time wrong** (11.2% diarization error rate), and hold music or a third voice makes it worse ([Benchmarking Diarization Models](https://arxiv.org/html/2509.26177v1)). Ask whether Quo can export stereo recordings; the research could not find out. Some services charge per channel, so stereo can roughly double cost.

**Privacy.** Sending calls to a foreign speech service is a cross-border transfer under POPIA section 72, which is usually handled with an operator agreement providing equivalent protection, or consent ([Michalsons](https://www.michalsons.com/focus-areas/privacy-and-data-protection/transfers-of-personal-information-outside-south-africa)). Self-hosting keeps audio in South Africa but gives weaker Zulu accuracy. Whether Azure and AWS offer speech services in their South African regions was not verified. Get legal advice before choosing.

## Reliable scoring needs evidence quotes, small scales and a human decision-maker

**Copy the industry pattern.** Vendors such as Observe.AI describe a human-defined scorecard scored question by question, with evidence attached and a calibration step comparing AI answers to human scores ([Observe.AI](https://www.observe.ai/platform/auto-qa)). Their accuracy claims are marketing; no independent benchmark was found. One competitor argues, reasonably, that "accuracy" only means agreement with your own calibrated humans on your own calls, and Aircall notes that questions where AI and analysts diverge most are usually badly worded and should be rewritten before rollout ([Aircall](https://aircall.io/en-gb/blog/ai-quality-assurance-call-centre/)). No published study of Claude on call QA was found.

**Make Claude show its evidence, then check it.** Anthropic's guidance for reducing invented content is to ask for word-for-word quotes first, let the model say "I don't know", and have it withdraw any claim it cannot support with a quote ([Anthropic docs](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations)). These techniques reduce but do not eliminate errors, so add a program that checks each quote actually appears in the transcript and flags those that do not. Research on AI judges shows they can be consistent yet wrong, and show biases toward rubric order and wording ([Reliability without Validity](https://arxiv.org/pdf/2606.19544); [arXiv 2506.22316](https://arxiv.org/pdf/2506.22316v4)). A 2026 study found a 0 to 5 scale agreed best with humans and 0 to 10 worst ([arXiv 2601.03444](https://arxiv.org/pdf/2601.03444)); the sources conflict on whether scoring each item separately beats scoring all items together, so test both on your own calls. The inferences drawn from this evidence: use simple verdicts (pass, fail, partial, not applicable, cannot determine), keep the scorecard text fixed and versioned, calculate weighted totals in code rather than asking Claude to add, and run critical items twice, sending disagreements to a person.

**Never trust the transcript on numbers.** Speech engines err most on names, phone numbers, order IDs and similar strings ([arXiv 2608.24314](https://arxiv.org/pdf/2608.24314)), and can sometimes produce words nobody said ([ACL Findings 2025](https://preview.aclanthology.org/display_plenaries/2025.findings-acl.1190.pdf)). So any item involving a quoted price or premium (for example R239), a date, a policy number, a recording or consent statement, a verbal "yes" from the customer, or overlapping speech should be marked "needs human audio check" with a timestamp, so the reviewer listens to a ten-second clip instead of the whole call.

**Keep people in charge.** Under South African law, general conduct duties require information to be correct and not misleading ([FAnews on the General Code](https://www.fanews.co.za/article/compliance-regulatory/2/general/1082/ethics-and-compliance-from-principles-to-practice/42402)), and law firms advise that POPIA's automated-decision rules (section 71) are less likely to be triggered where a manager reviews and finalises a score, with employees able to see the evidence and respond ([Bowmans](https://bowmanslaw.com/insights/south-africa-ai-in-the-workplace-2-of-6-popia-considerations/)). Whether regulators require recording of telephonic advice, or what consent rules apply to recording for QA, was **not verified**; obtain a legal opinion. No sampling-rate or calibration-frequency standard was found.

## Recommendations for Innovate

First, confirm what your Cowork actually does. Ask whoever set it up, or look at a recent session, to see where the text came from (Quo, a connector, or a script Claude ran). Do not assume Claude heard the call.

Second, run a small transcription test before any scoring work. Take 20 to 30 real calls (stereo if Quo can provide it), have a person correct the transcripts for a few of them, and compare Deepgram Nova-3 (multilingual, with keyterms), ElevenLabs Scribe v2, Azure Speech with custom speech, and Quo's own transcripts, with Whisper large-v3 as a privacy-friendly baseline. Measure overall errors and, separately, errors on numbers and product terms such as R239, DebiCheck, Netstar and Cartrack. That bake-off is the project's real decision point; every engine ranking in this report is **unverified**.

Third, build the scoring as a Cowork skill that reads a transcript file (or connector transcript), scores each item against your written scorecard with exact quotes and timestamps, flags items for human audio checks, and writes a PDF into your connected folder. Do not make in-Cowork Whisper your primary design unless a test proves it works on your plan, and label every output "draft pending human review".

Fourth, before go-live, have two QA people score 50 to 100 calls independently, compare with Claude per item using a chance-corrected agreement measure (Cohen's kappa), rewrite items where they disagree, and repeat whenever the scorecard, the prompt or the model changes. Make a human sign-off mandatory before any score affects pay or discipline. Get legal review of recording consent, cross-border transfer and automated-decision questions.

## Conclusion

The practical shift is from asking "can Claude listen?" to asking "how good is our transcript?". Claude is a capable reader and rule-checker, but it sees only what the transcription engine wrote down, and on Zulu-English phone calls that is the least-measured link in the chain. The strongest immediate lever is not a smarter prompt, it is a two-hour comparison of transcription engines on your own recordings.

The other novel implication is that Claude's evidence quotes are only as trustworthy as the checks around them. Because transcripts misrecord exactly the numbers and consent phrases your scorecard cares about, the winning design treats Claude as a first-pass reviewer that points a human to the right ten seconds of audio, rather than as an automatic judge. Re-check Anthropic's release notes periodically, since native audio input would change this advice, but nothing found suggests it is imminent.
